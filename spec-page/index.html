§3.4  The button rule

§6Type

Geist for display, Inter for prose, Geist Mono for identifiers. No serif. Headings are set in sentence case in the source — text-transform: capitalize cannot tell a preposition from a noun, which is why the live hero reads “Of” and “With”.

§6.5  The handwriting

One word per page, maximum. Never in a heading, a label, a button, or anything a reader must act on. It is a wink, and a wink repeated is a twitch.

Minimum size

The wordmark is 5.7:1 wide. Below about 96px the counters close and it reads as a smear, which is exactly what happens in a 32px favicon slot. Use the LM glyph on a tile instead — the tile is what lets one favicon work on every ground.

§8.5  The ASCII mark

The figlet wordmark lmcache/banner.py prints at startup. It has already been printed on swag, and it is an optional third mark for physical and playful contexts — stickers, pens, lanyards, booth texture, the quiet background field on event cards. Not a website header, not a lockup with the vector wordmark, and not a name badge.

_ __ __ ____ _ | | | \/ | / ___|__ _ ___| |__ ___ | | | |\/| || | / _` |/ __| '_ \ / _ \ | |___| | | || |__| (_| | (__| | | | __/ |_____|_| |_| \____\__,_|\___|_| |_|\___|

It is monospace-dependent. If the font is missing the character grid collapses and the letterforms dissolve. Ship it as text SVG only where a webfont is guaranteed; for print, swag and any vendor handoff, outline the text first or send the raw .txt and let the vendor set it in their own mono.

The CLI prints Solarized #cb4b16 and #2aa198, which is correct in a terminal. Printed and screen forms take the brand pair, or the whiteprint pair on bone stock. Three orange-and-teal pairs now exist in the LMCache world, and they stay unreconciled on purpose.

§9Whiteprint

The house image style for technical figures on the blog. Part of this system, and not this system. Its inks are fixed literals that are never themed, because a whiteprint is a printed sheet and sits on its own paper whether the page around it is light or dark.

Where whiteprint governs

Technical figures in blog posts, including the og:image hero for a post with a sheet set. Diagrams in a technical talk. Illustration for a deep-dive explainer.

Where it does not

Marketing site, docs chrome, event cards, signage, badges, non-figure slides, swag. A whiteprint sheet on an event poster turns the poster into a figure without an argument.

The one useful crossing

A whiteprint sheet is the right image for an event about the thing the sheet draws. It keeps its own paper and its own four inks, and sits on the card with a margin of Ink or Mist around it.

Never

Bled to the card edge. Recolored to the brand pair. Brand type set on top of it. The card frames the sheet; the sheet does not become the card.

Square cards default to the Ink ground. A square event thumbnail is usually seen at 200px in a list beside a dozen others, and Ink with an orange kicker separates from a wall of white cards in a way Mist does not. Check every square at 200px before shipping it — if the second title line stops being readable, the title is too long, and the fix is a shorter title rather than smaller type.

Delete the guides group before export. It is magenta and green specifically so it is impossible to miss if it survives to proof.
